# Backend settings review — 2026-11-27

This review covers settings HTTP contracts and their persistence, authorization and downstream effects. It does not certify production configuration, store billing, physical-device permissions or translated copy.

| Setting / control | Backend path and reviewed behavior | Evidence |
| --- | --- | --- |
| Account email | `GET /me/account` projects only the authenticated user's ID/email. No email-change endpoint is exposed. | `MeController`; authentication middleware rejects closed accounts. |
| Discovery distance/age/gender | `GET/PATCH /me/discovery-settings`; nullable partial fields, adult age bounds 18–100, min≤max, radius 1–300, supported gender preference. User row lock serializes changes; transaction persists settings. Legacy `POST /me/radius` validates 1–300. | `DiscoveryAndProfileTests` invalid inputs, strict-first expanded distance, adult age fallback, blocked/paused/incognito eligibility. |
| Location / automatic updates | Same discovery endpoint validates coordinates together, finite/range bounds, requires enabled automatic location, records timestamp and movement; location centre is separate from public hometown. No exact coordinates returned by the settings view. | `DiscoveryAndProfileTests` Spain relocation, account isolation, movement boundaries. Actual GPS/OS permission is device-side. |
| Activity privacy / incognito | `GET /commerce/state`, `PATCH /commerce/privacy`; verified entitlement gates enabling. Each supplied flag is changed independently under account row lock; omitted fields remain unchanged. Disabling remains available after expiry. | Added `PrivacyPatchPreservesOmittedPreferencesAcrossClientsAndAccounts`, `ExpiredEntitlementDoesNotPreventDisablingOnePrivacyPreference`; existing presence/feed premium tests. |
| Pause/reactivate | `GET /me/account/status`, `PATCH /me/account/pause`; explicit non-null boolean required. Pause affects discovery and received likes, preserves existing conversations. Lifecycle exclusive lock serializes changes with closure. | `AccountManagementTests`; new empty/null pause regressions in `SettingsValidationTests`. |
| Account deletion | `POST /me/account/removal`; confirmation/password/rate limit, closure revokes subsequent authenticated calls, removes public profile/conversation/relation data, retains pseudonymous payment replay/safety record. External asset cleanup honestly remains pending when appropriate. | `AccountManagementTests`; no real account deleted during this audit. |
| Blocked profiles | `GET /blocks` only outgoing blocks; historical identification snapshots cannot expose newly added/removed images, reverse-block/private identities protected. `POST /blocks` and `DELETE /blocks/{id}` pair/lifecycle locks, only caller's outgoing block, clears relation/swipe state; unblock never revives old conversation. | `AccountBlockLifecycleTests`, `ChatAuthorizationTests`. |
| Report | `POST /reports` validates nonempty reason≤1000, target nonzero/not self. Missing target now returns 404 instead of foreign-key server failure. Existing retained closed-account key can still receive safety reports. | New missing-target/non-persistence HTTP regression in `SettingsValidationTests`. |
| Notification installation / logout cleanup | `POST /me/device-token`, `POST /me/device-token/clear`; versioned installation ownership, stale conflict and tombstone prevent an old logout clearing another account's newer binding. | `PushInstallationTests`; existing PostgreSQL integration checker. Permission prompt and OS delivery require actual phones. |
| Premium / Boost / restore | `GET /commerce/catalog`, state, sync, purchase-status; provider-verified entitlements/receipt ownership, no client-supplied grants. Boost requires visible unpaused profile and balance, serialized consumption. | `CommerceTests`, `RevenueCatVerificationTests`; no checkout enabled or paid provider activated. Receiptless interrupted checkout remains a separate launch gate. |
| Session access | JWT validation requires existing nonclosed authenticated user; routes above require authorization, no caller-supplied owner ID is used for settings. | `ChatBearerAuthentication.ValidateAccount`; account closure HTTP tests. Logout is local token/installation cleanup, not a server-wide revoke-all-sessions feature. |
| Language | App preference and system-language selection are local frontend settings; no backend language-setting endpoint is falsely implied. | Frontend audit maintained separately. |

Persistence evidence uses separate HTTP clients and fresh EF contexts against the test database, plus the existing database-backed endpoint suite. This audit did not restart a real deployed server or modify production data. The existing synthetic backup/restore and PostgreSQL checks remain separate checks; do not describe fresh contexts as a deployed restart test.

No database schema/migration changes, SMTP configuration, key rotation, production deployment or billing activation were performed.
